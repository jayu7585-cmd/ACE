# wiki-query: 위키에 묻고, 좋은 답은 위키로 되돌리기

이 스킬은 `CLAUDE.md` 4.2절(Query)을 실행하는 절차서다. 규약은 `CLAUDE.md` 3절을 따르며, 충돌하면 **CLAUDE.md가 우선**한다.

핵심은 두 가지다.
1. 답은 **위키에 이미 컴파일된 지식**에서 나온다. 원자료를 처음부터 다시 뒤지지 않는다.
2. 좋은 답은 채팅 기록 속에 사라지게 두지 않고 **위키로 되돌린다**. 질문도 ingest처럼 지식을 누적시킨다.

## 0. 인자 해석

`$ARGUMENTS`
- **질문 본문**: 답할 질문. 비어 있으면 무엇을 물을지 사용자에게 묻는다.
- **`저장`**: 답을 `wiki/syntheses/`에 저장한다. 따로 묻지 않는다.
- **형식 키워드**: `표`, `슬라이드`(Marp), `차트`, `캔버스`. 없으면 질문에 맞는 형식을 고른다(4단계).

## 1. 위키 탐색

1. `wiki/index.md`를 **먼저** 읽는다. 질문과 관련된 항목을 고른다.
2. 보조 검색을 한다. 한국어 용어와 영어 원어를 함께 넣는다:
   `python3 .claude/skills/wiki-query/scripts/search.py 손실회피 "loss aversion" 프레이밍`
3. 찾은 페이지를 읽는다. 우선순위는 topic → theory/concept → synthesis → source 순이다.
4. 읽은 페이지의 링크를 **한 단계** 더 따라가서, 답에 필요한 관련 페이지를 확인한다.
5. `wiki/overview.md`의 핵심 논지와 관련 있는지 확인한다.
6. 과거에 비슷한 질문을 다룬 synthesis가 있는지 확인한다(`grep "query |" wiki/log.md`). 있으면 그 답을 출발점으로 삼고, 달라진 점만 보강한다.

## 2. 근거 충분성 판단

답을 쓰기 전에 위키가 이 질문을 얼마나 뒷받침하는지 판정한다.

| 판정 | 기준 | 대응 |
|---|---|---|
| **충분** | 관련 페이지와 출처가 있고 질문의 핵심을 덮음 | 위키만으로 답한다 |
| **부분** | 일부만 덮거나 출처가 1개뿐 | 위키로 답하고, 빈 곳은 "위키 밖 일반 지식"으로 구분해 보충한다 |
| **부족** | 관련 페이지가 거의 없음 | 그 사실을 먼저 말한다. 일반 지식으로 잠정 답변을 하고, ingest할 자료를 제안한다 |

- 위키로 부족할 때만 `raw/`의 원자료를 직접 참조한다. 이 경우 그 자료가 ingest되지 않았다면 `/wiki-ingest`를 제안한다.
- 필요하면 웹 검색을 쓸 수 있다. 다만 결과는 "위키 밖 (웹)"으로 표시하고, 좋은 자료면 `raw/`에 넣어 ingest하도록 제안한다.

## 3. 답변 작성

**구조** (CLAUDE.md 1절 응답 스타일). 짧은 사실 확인 질문이면 몇 문장으로 답하고, 분석·비교·종합 질문이면 다음 3단 구조를 쓴다.
- **서론**: 개념, 원리, 핵심 연구자, 배경
- **본론**: ① 컨텍스트 차원 → ② 텍스트 차원 → ③ 통합적 차원
- **결론**: 요약, 논의, 제언

**근거 표시**
- 위키에 근거가 있는 문장은 끝에 위키링크를 단다: `([[손실회피]], [[sources/1979-Kahneman-Prospect-Theory]])`
- 위키에 없는 내용은 `(위키 밖 일반 지식)` 또는 `(위키 밖 · 웹)`으로 표시한다.
- 자료 사이의 상충(`[!warning] 상충`)이 관련되어 있으면 한쪽만 고르지 말고 양쪽을 제시한다.
- 효과크기, 표본, 재현성 논란이 위키에 기록돼 있으면 답에도 반영한다. 연구 결과를 과장하지 않는다.
- 답 끝에 **근거 수준**을 한 줄로 밝힌다: `근거: 위키 페이지 n개, 출처 m건 · 판정: 충분/부분/부족`

## 4. 출력 형식

| 질문 유형 | 형식 | 저장 위치 |
|---|---|---|
| 설명, 분석, 종합 | 마크다운 답변 | 채팅 (file back 시 `wiki/syntheses/`) |
| 두 개 이상 비교 | 비교표 + 해설 | 위와 같음 |
| 발표, 수업 자료 | Marp 슬라이드 | `outputs/slides/YYYY-MM-DD-주제.md` |
| 수치, 추세, 관계 | 차트(matplotlib PNG) | `outputs/charts/YYYY-MM-DD-주제.png` |
| 개념 관계도 | Obsidian Canvas(`.canvas`) | `outputs/YYYY-MM-DD-주제.canvas` |

- Marp 슬라이드는 첫 줄에 `marp: true`가 든 frontmatter를 두고, 슬라이드는 `---`로 나눈다. 각 슬라이드 하단에 근거 위키링크를 단다.
- 차트는 **위키에 기록된 수치만** 사용한다. 수치를 지어내지 않는다. 차트를 만들기 전에 `dataviz` 스킬을 읽는다.
- `outputs/`의 산출물은 파생물이다. 관련 synthesis 페이지에서 `![[outputs/…]]`로 연결한다.

## 5. 되돌려 저장하기 (file back)

**저장을 제안하는 경우**: 비교·분석, 여러 페이지를 가로지르는 새로운 연결, 교육 현장 적용 설계, 사용자가 다시 찾아볼 법한 답. 단순 사실 확인은 제안하지 않는다.

`저장` 인자가 없으면 답 끝에 한 줄로 묻는다: `이 답을 [[syntheses/…]]로 저장할까요?`

저장할 때:
1. **페이지 작성**: `wiki/syntheses/YYYY-MM-DD-질문요지.md`에 `templates/synthesis.md` 구조로 쓴다. frontmatter에 `question:`(원 질문), `sources:`(인용한 source 페이지 수)를 채운다. 채팅 답변을 그대로 붙이지 말고, 링크와 근거 표시를 갖춘 위키 문체로 다듬는다.
2. **교육 적용 설계안**이면 `wiki/applications/`에 `templates/application.md`로 쓴다.
3. **역링크**: 답의 근거가 된 주요 개념·이론·주제 페이지에 `## 관련 종합` 절을 두고(없으면 만든다) 새 페이지 링크를 추가한다. 페이지 전체를 덮어쓰지 않고 Read → Edit로 고친다.
4. **새 발견 반영**: 답을 쓰다가 기존 페이지에 없는 연결이나 상충을 발견했다면 해당 페이지에도 반영한다. 출처가 있으면 일반 문장으로, Claude의 추론이면 `[!note] 종합(LLM)` 콜아웃으로 쓴다.
5. **overview 점검**: 핵심 논지에 영향을 주면 overview.md를 갱신한다.
6. **index.md**: Syntheses 또는 Applications 섹션에 항목을 추가한다: `- [[…]] — 한 줄 요약 (sources: n, seed)`
7. **검증**: `python3 scripts/wiki_lint.py`로 이번 작업이 만든 문제를 모두 고친다.

## 6. 빈틈 기록

답하면서 드러난 위키의 빈틈은 버리지 않는다.
- 관련 페이지에 `> [!question] 열린 질문`으로 남긴다.
- 채울 수 있는 자료(논문, 저자, 검색어)를 사용자에게 제안한다.

## 7. log.md 기록

위키가 바뀐 경우(file back, 빈틈 기록, 기존 페이지 보강)에만 **맨 아래에** 추가한다. 위키를 건드리지 않은 단순 질의는 기록하지 않는다.

```
## [YYYY-MM-DD] query | 질문 요지
- 질문: …
- 근거 판정: 충분/부분/부족
- 생성: [[syntheses/…]]
- 갱신: [[…]], [[…]]
- 열린 질문: …          ← 없으면 생략
```

git 저장소이면 커밋한다: `query | 질문 요지`

## 하지 말 것

- index.md를 건너뛰고 raw/부터 뒤지지 않는다
- 위키 근거와 위키 밖 지식을 섞어 쓰지 않는다 (항상 구분 표시)
- 위키에 없는 수치나 인용문을 지어내지 않는다
- 사용자 동의 없이 synthesis를 저장하지 않는다 (`저장` 인자가 있을 때만 예외)
- 기존 페이지를 Write로 통째로 덮어쓰지 않는다 (Read → Edit)
