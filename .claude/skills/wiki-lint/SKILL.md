# wiki-lint: 위키 건강검진

이 스킬은 `CLAUDE.md` 4.3절(Lint)을 실행하는 절차서다. 규약은 `CLAUDE.md` 3절을 따르며, 충돌하면 **CLAUDE.md가 우선**한다.

위키가 커질수록 관리 부담은 가치보다 빨리 늘어난다. lint는 그 부담을 주기적으로 갚는 작업이다. 원칙은 **진단 → 보고 → 승인 → 수정**이다. 사용자 승인 없이 내용을 바꾸지 않는다.

## 0. 인자 해석

`$ARGUMENTS`
- **`구조`**: 1단계(스크립트 점검)만 한다. 빠른 점검용.
- **`내용`**: 2단계(내용 점검)에 집중한다.
- **`전체`** 또는 비어 있음: 둘 다 한다.
- **범위**(예: `wiki/concepts`, `휴리스틱`): 내용 점검을 그 폴더나 주제로 좁힌다. 스크립트 점검은 언제나 전체를 대상으로 한다.
- **`자동수정`**: 4단계의 A등급(기계적 수정)은 승인 없이 바로 고친다. B·C등급은 여전히 승인을 받는다.

## 1. 구조 점검 (스크립트)

다음 두 스크립트를 실행한다.

```bash
python3 scripts/wiki_lint.py
python3 .claude/skills/wiki-lint/scripts/deep_check.py
```

| 스크립트 | 찾는 것 |
|---|---|
| `wiki_lint.py` | 깨진 링크, 고아 페이지(들어오는 링크 없음), index 미등재, frontmatter 누락 |
| `deep_check.py` | `sources:` 수와 실제 인용 수 불일치, index 메타데이터 불일치, 출처 없는 지식 페이지, 링크 없는 언급(교차참조 후보), 미해결 상충·열린 질문 콜아웃, 오래 방치된 seed 페이지, 마지막 lint 이후 ingest 건수 |

스크립트 결과는 **후보**다. 특히 "링크 없는 언급"은 짧은 별칭이 다른 단어 속에 우연히 들어 있어 잡힐 수 있으므로, 문맥을 확인해 진짜인 것만 남긴다.

## 2. 내용 점검 (Claude의 판단)

스크립트로는 찾을 수 없는 문제를 직접 읽고 찾는다. 페이지가 많으면 범위를 좁히거나 hub 페이지(topics, overview)부터 읽는다.

1. **페이지 간 모순**: 같은 개념·효과를 다른 페이지가 다르게 서술하는데 `[!warning] 상충` 표시가 없는 경우. 개념 정의, 효과의 방향과 크기, 연구자 귀속, 연도를 특히 확인한다.
2. **낡은 주장**: 새 source가 들어와 수정되거나 반박된 주장이 다른 페이지에 그대로 남아 있는 경우. 날짜가 최근인 source 페이지부터 거꾸로 추적한다.
3. **재현성 표시 누락**: 재현성 논란이 알려진 효과(예: 자아고갈, 일부 점화효과, 파워포즈)를 확정된 사실처럼 쓴 경우.
4. **페이지가 없는 중요 개념**: 여러 페이지에서 반복해 언급되는데(대략 3회 이상, 2개 이상의 source) 자기 페이지가 없는 개념·인물·이론.
5. **빠진 교차참조**: 서로 긴밀한데 연결되지 않은 페이지 쌍 (예: 이론과 그 핵심 개념, 대립하는 두 이론). 1단계의 "링크 없는 언급"과 함께 본다.
6. **구조 문제**: 한 페이지가 너무 커져 나눠야 하는 경우, 거의 같은 두 페이지(합치기 후보), 주제 허브가 필요한 개념 묶음.
7. **overview 정합성**: overview.md의 핵심 논지가 현재 위키 내용을 반영하는지.
8. **자료 공백**: 위키의 중요한 주장인데 출처가 1개뿐이거나 오래된 것. 웹 검색으로 보강할 수 있는 공백.
9. **미해결 콜아웃 정리**: 기존 `[!warning] 상충`과 `[!question] 열린 질문` 가운데, 이후 ingest된 자료로 이제 해결할 수 있는 것.

## 3. 보고

진단 결과를 등급별로 보고하고 **멈춰서 승인을 기다린다.**

| 등급 | 성격 | 예 | 처리 |
|---|---|---|---|
| **A 기계적** | 내용 판단이 필요 없음 | 깨진 링크 수정, index 누락 추가, `sources:` 수 정정, frontmatter 보완, 역링크 추가 | 일괄 승인 (`자동수정`이면 바로 수정) |
| **B 내용** | 서술을 바꿈 | 상충 콜아웃 추가, 낡은 주장 수정, 재현성 표시, seed 페이지 신설, overview 갱신 | 항목별 승인 |
| **C 구조** | 페이지를 합치거나 나누거나 이름을 바꿈 | 페이지 병합·분할, 주제 허브 신설, 이름 변경 | 제안만. 사용자가 명시적으로 요청할 때만 실행 |

```
🩺 위키 건강검진 — 페이지 N개 · 마지막 lint 이후 ingest K건
구조: 깨진 링크 a · 고아 b · index 누락 c · 장부 불일치 d
A 기계적 (n건): …
B 내용 (n건):
  B1. [[손실회피]] ↔ [[전망이론]]: 손실회피 계수 서술 상충 (2.25 vs 약 2) — 상충 콜아웃 추가 제안
  B2. …
C 구조 (n건, 제안만): …
어떤 항목을 고칠까요? (예: "A 전부, B1, B3")
```

## 4. 수정

승인된 항목만 고친다.
- 기존 페이지는 반드시 Read → Edit로 고친다. 통째로 덮어쓰지 않는다.
- 상충은 한쪽을 지우지 않고 `[!warning] 상충`으로 양쪽 근거를 병기한다.
- 낡은 주장은 지우지 않고 `~~취소선~~`과 함께 새 근거를 달거나, 문장을 고치면서 "이전에는 X로 보았으나 [[sources/…]] 이후 Y"처럼 변화를 드러낸다.
- 새로 만든 seed 페이지와 고친 페이지는 frontmatter의 `updated`를 오늘 날짜로 바꾼다.
- 사용자가 직접 쓴 흔적은 건드리지 않는다.
- `raw/`와 `log.md`의 기존 항목은 어떤 경우에도 수정하지 않는다.

수정 후 1단계의 두 스크립트를 다시 돌려 **수정 전후 수치**를 비교한다.

## 5. 탐구 제안

lint의 마지막 산출물은 **다음에 할 일**이다.
- **새 질문** 3–5개: 위키의 빈틈과 상충에서 나온 질문. 판단 및 의사결정 연구와 교육 적용 관점에서 쓴다.
- **찾아볼 자료** 3–5개: 공백을 메울 논문, 저자, 검색어. 확실하지 않은 서지 정보는 "검색어"로만 제시하고 지어내지 않는다.
- 제안한 질문은 관련 페이지나 overview.md에 `> [!question] 열린 질문`으로 남길지 사용자에게 묻는다.

## 6. log.md 기록과 커밋

**맨 아래에** 추가한다.

```
## [YYYY-MM-DD] lint | 범위
- 진단: 깨진 링크 a · 고아 b · index 누락 c · 장부 불일치 d · 내용 이슈 e
- 수정: A n건, B n건 ([[…]], [[…]])
- 보류: C n건 (요지)
- 제안 질문: …
- 제안 자료: …
```

git 저장소이면 커밋한다: `lint | 범위`

## 하지 말 것

- 승인 없이 B·C등급을 수정하지 않는다
- 상충하는 주장 중 한쪽을 조용히 지우지 않는다
- 페이지를 삭제하지 않는다 (병합이 필요하면 제안만)
- 스크립트 결과를 확인 없이 그대로 고치지 않는다 (링크 없는 언급은 특히 오탐이 있음)
- 확인되지 않은 서지 정보를 제안 자료로 내놓지 않는다
